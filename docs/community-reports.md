# 社区举报与钓位纠错

2026-11-20更新。此流程处理社区共享鱼情、心得、钓位及单条评论，不是向政府部门报案，也不读取私密水域线索、聊天或私人日志。

## 使用路径

- 鱼情详情「举报这条内容」或钓位详情「信息失效 / 提交纠错」：填写具体问题后提交。失败保留输入，关闭表单后在当前页面重新打开仍保留；离开页面或切换账号清空未提交内容。
- 别人的正常评论显示「举报」，自己的评论不显示。共用一个底部表单，字段ID与动态举报区分；触区至少48px、空输入定位、Escape返回原动作、断网保留说明，离页／换账号清空。
- 我的 → 我的举报：查看本人提交的说明、处理结果与时间。不展示审核员或其他举报人身份。
- 设置 → 内容审核 → 社区举报与纠错：仅拥有私有审核员成员资格的账号可读取。待处理按最早提交排序，已处理按结案时间倒序；每页12条。
- 每条处理先看当前全文与照片，再选择明确结果。照片未能读取时不能选择不处理内容；可重新读取照片。旧版本冲突必须重新读取，不能直接覆盖。
- 隐藏后可从已处理详情进入原「内容审核」查看状态；恢复内容仍由原审核流程校验权限、版本与范围，不更改历史举报结论。

## 业务与权限

数据库是状态权威；前端不能直接写状态。`pending → actioned / dismissed / unavailable` 是一次性结案：

| 操作 | 条件 | 内容影响 |
| --- | --- | --- |
| 隐藏内容并结案 | 最新版本仍为可审核、已发布的鱼情、钓位或评论 | 同一事务隐藏内容、记录作者可见说明、结束举报 |
| 不处理内容并结案 | 当前内容仍可审核且已发布 | 不修改原内容，记录未采取措施的原因 |
| 按内容不可用结案 | 已删除、私密化，或不再是已发布版本 | 仅结束举报，不恢复、不删除原内容 |

处理说明必填，最多500字；隐藏说明也会提供给作者，不应包含举报人信息。处理记录是历史决定，不代表当前内容状态。作者可能修正重提，也可能经另一条审核流程恢复。

不能处理自己提交的举报或涉及自己内容的举报。权限从 `fishing_private.moderators` 当前成员关系读取，不依赖用户可编辑的 metadata。撤权后的请求拒绝，页面清空内容并立即移除弹层。身份或页面变化会使在途回包失效。

普通用户原表仅允许读取自己的举报；审核员通过最小投影接口工作，不返回举报人ID。已撤回或删除的目标不再向审核员返回原文、原标题、照片或坐标。处理请求的幂等回执也重新核对目标是否私密化。审计只保存操作所需信息，不复制举报人的原始说明和目标标题；举报记录随举报人资料删除而级联清理，内部处理审计不包含其身份。

同一用户对同一目标只保留一条举报，重复提交返回原记录，不覆盖原说明或重复处理。新举报每用户滚动24小时最多20条，限额不阻止原请求回执恢复。后续版本再次举报、补充证据、申诉和重新开案尚未实现，不能把当前去重规则称为完整申诉系统。

评论只在 `published ↔ hidden` 间审核切换，和不可逆的本人删除分离。隐藏后只有作者在仍能访问原动态时能看到原文和说明，不能回复隐藏评论；其他人及匿名在RPC、原表RLS、数量与分页中均看不到。所有引用（包括作者自己看到的引用）实时投影时过滤隐藏原文，恢复后才重新显示。作者视角的评论数包含本人可见的隐藏评论，其他视角不包含。当前没有评论实时订阅：已打开页面在重新进入／刷新后重新核验，不能宣称实时抹除所有客户端既有副本。

评论审核投影只允许父动态非私密且未删除；允许审核员处理仍共享但处于待审／隐藏状态的父动态内的评论，但恢复评论不会通过审核或恢复父动态。转私密／删除后投影不返回评论原文或动态标题，旧回执不重新发布。评论举报仅在父动态已发布且提交人当前可见时接受，遵守双向拉黑，标签只存「评论」而不复制正文／作者姓名。审核保留当前成员资格、自审拒绝、版本冲突、幂等和原限流；写入统一锁顺序为用户 → 父动态 → 评论，举报处理另在父动态之前锁定举报记录。

个人资料举报沿用既有服务端目标类型，暂不新增个人资料举报入口；可以查看与说明不采取措施，不能用此功能封禁账号。账号限制和账号封禁联动仍待完整权限与审计实施。
