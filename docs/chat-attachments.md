# 图片与内容卡片聊天

2026-11-19。这是文字聊天的增量，不是 Realtime、推送或离线发送队列。

## 使用路径与状态

- 聊天页「照片」→ 相册／拍照 → 预览确认 → 上传副本 → 发送中 → 已发送。一次一张；正文草稿不受影响。网络失败留在原消息上重试，已经确认上传的照片不会重复上传。不支持的格式／尺寸提供重新选择，不做无效重试。
- 鱼情／钓位详情「发给钓友」→ 选择好友 → 确认发送 → 查看聊天。关闭选择不发送；失败保留接收人及消息标识。只分享已发布、非私密且双方当前可读的内容，分享不会改变原范围。
- 短时图片草稿、上传进度和失败消息仅保留于本次页面；退出页面前完成发送。文本草稿仍按账号和会话保存。尚无持久化离线发件箱。
- 删除好友／拉黑停止新消息，保留原会话历史。之前已经发送的图片属于保留的聊天历史，不能通过拉黑追回；内容卡片仍按当前内容权限重新检查。已落库消息的丢失回执可以用相同标识取回，不会变成新消息。

## 数据与权限

远端迁移 `20261119152501_fishing_chat_attachments` 已应用到 `tlfmfokyhahlpzmpliad` 并回读。

- `messages.kind` 区分 `text/image/post/spot`；旧记录默认 text。图片 body 固定为 `[图片]`，内容卡片仅保存引用和通用类型文字，不保存旧标题、正文、封面、精确／模糊坐标或到达说明。标题和鱼种／钓法／水域类型／位置精度提示由服务器每次投影当前获准字段。用户自行写入标题的文字不是坐标脱敏器的处理对象。
- 受 RLS 保护的 `media_assets.message_id` 关联一条消息，一条图片消息最多一张。上传资产必须是发送人自己的未挂载上传；数据库单父约束与所有现有挂载写入共同阻止从私人日志、上报、其他消息或动态挪用图片。
- Storage 仍为私有桶，先按 RLS 校验再签发 60 秒地址。消息双方可读图片；其他人、游客、仅具有社区审核员身份的人不可读。客户端仅在新一轮授权成功、资产身份／路径匹配且原地址未超过45秒时复用内存地址。已签发的链接和收件人下载／截图不能即时追回。
- 原 `fishing_read/write` invoker 包装不变，内部 `chat_send/chat_content/message_json/chat_card` 留在不暴露的 schema 且禁止客户端直接执行。没有新增全权公用 RPC，没有动登录配置。
- 写入复用原用户限流和好友双方锁。`sender_id + client_id` 幂等及服务端序号仍是权威；卡片投影也用于重试回执，撤回后不会返还旧快照。
- 读取保留最近100条、向前翻页和增量补齐。已载入附件／引用另外分批（每批最多100条）重新鉴权，因此“没有新消息”不会阻止旧卡片更新。读取失败、离开页面或切换账号清空已确认附件预览；未发送照片仍是自己的临时稿。

## 设计依据与复用

沿用 Pro `MobileAction`、`MobileBottomSheet`、可见视口与输入可访问属性，业务照片用现有 `FishingPhotos`，压缩和去位置元数据沿用共享图片准备模块与线上上传函数。本轮没有修改生成目录，也没有修改 Pro 通用源码。

Apple 的 `image-views.md › Best practices` 用于可点击图片按钮语义，`collaboration-and-sharing.md › Best practices` 用于简明分享范围，`sheets.md` 用于上下文内选择确认，`virtual-keyboards.md` 用于保持输入区可见。UI UX Pro 的 `image upload error recovery` 命中原位恢复与可访问错误，Vue 查询只采用派生状态建议。现有三套皮肤的语义色保持不变，不加装饰元素。

[Flyer Chat 官方仓库](https://github.com/flyerhq/flutter_chat_ui) 的不同消息类型独立渲染与模块组织用于设计参考，仓库当前标明 Apache-2.0；未引入 Flutter 依赖、复制其源码或图片。Storage 权限参考 [Supabase 私有桶](https://supabase.com/docs/guides/storage/buckets/fundamentals) 和 [访问控制](https://supabase.com/docs/guides/storage/security/access-control)。
