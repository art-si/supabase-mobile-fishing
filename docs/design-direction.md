## 设计意图

2026-11-20官方渠道查询：游客无需先登录即可选择事发省市县，查询与私密材料分开存放。地区表单复用Pro的字段、搜索选择器；同一业务组件用于游客查询和已登录编辑，不新造控件。Apple `entering-data.md › Best practices` 与 `lists-and-tables.md › Content` 用于明确标签、地方渠道优先和简短机构名，`alerts.md › Buttons` 用于拨号前显示具体单位／号码、取消优先。UI UX首次查询 `forms progressive disclosure mobile` 未直接命中渐进披露，收窄到 `form visible labels` 后采用 Form Labels／Input Labels；没有添加新色彩、动效或导航。15张H5截图逐张查看，覆盖320/375/440、横屏、宽屏、三套皮肤、深色、150%／200%文字、键盘焦点及确认框。模拟会话只用于检查私密草稿与游客筛选隔离，不代表真实登录或官方电话接通；未触发任何外部请求。

2026-11-20图文发布：按已确认方案减少必填项，动态标题选填、正文或照片至少一项，日志保留标题／日期要求。Apple `entering-data.md › Best practices` 用于明确必要输入，`drag-and-drop.md › Best practices` 与UI UX `dragging movements reorder photos` 用于点按／键盘排序，`sheets.md › Best practices` 用于一个就近弹层与明确关闭。复用Pro动作、表单、弹层，照片保持原比例预览，无标题正文不再被重复绘制为标题。沿用原主题／字号／间距，不增加装饰或导航。截图复看修复过长占位文案及禁用按钮在深色下的浅底；验收规则与边界见[图文发布](content-publishing.md)。

2026-11-20小程序包体：Apple `typography.md › Using system fonts` 的平台可读字体原则与 `accessibility.md › Vision` 的大字适配，用于小程序不再内嵌完整中文字库；字重、字号、层级、图标和三皮肤不变。UI UX Pro查询 `font loading mobile`、`route bundle splitting` 命中字体加载／回退与按功能拆包，条目偏Web，采用性能原则而非照搬Web加载API。Pro只提供默认不变的可选开关，钓友集微信端选择关闭，H5/App及其他Pro应用保持原字体。没有引入远程字体、装饰、导航或动画。H5系统字体替代测试不能证明微信字体指标与真实设备大字支持，设备验收另记；包体与路由证据见[小程序包体](miniapp-package.md)。

实际回看本轮系统字体截图后，地图搜索页320px大字的六字标题出现最后一字单独一行。采用更直接的业务名称「地点搜索／选择地点」，保留高德数据来源，不缩小文字、不硬插换行。UI UX `orphan heading line balance` 命中自然换行与跨字体检验，未将Web的平衡换行启发式当作微信排版保证。最终119项H5回归含浏览／选点标题单行断言，两个深色大字截图已查看。

2026-11-20地图回访：采用Apple `search-fields.md › Best practices` 的输入即查找与简化结果、`maps.md › Best practices` 的清楚选中范围及保留底图，UI UX查询 `search autocomplete keyboard navigation` 命中Autocomplete与Keyboard Navigation。沿用现有Pro联想框和安静的文字说明，不增加搜索按钮／装饰卡片。生命周期修复只更新公共提醒的加载状态，保留本人的圈选草稿；来源和空范围说明保持可见，不以颜色代替可信度。已回看真实底图375px、圈选375px及320px深色24px文字，联想的键盘／中文输入法与五类视口检查通过；全国官方边界及真机GPS不在这些截图证据内。

2026-11-20评论举报：每条别人的评论只增加一个文字动作，复用一个共享的Pro底部表单，不增加导航／首页运营卡片。Apple `sheets.md › Best practices` 用于单一任务、明确关闭和一次一个弹层；`feedback.md › Best practices` 用于就近显示提交进度、作者可见处理说明。UI UX Pro 的 `modal focus return` 命中 Focus States／Focus Appearance，因此检查Escape关闭回到原动作、空说明聚焦输入框、48px触区。评论隐藏以文字状态表达，作者仍可删除；其他回复的引用显示中性占位，不残留原文。恢复按钮明确叫「恢复评论」，不借用动态「通过审核」的含混文案。保持原语义色、字号和66组既有对比约束，未新增颜色、动效或装饰。实际检查320/375/440、横屏、宽屏、320深色24px根字号、三套皮肤明暗；本地与远端截图均已查看。截图发现已填写有效说明后仍保留必填错误，已改为输入有效时清除；加载鱼形在H5用浏览器原生img呈现同源位图，避免Uni图片组件晚到回调访问已卸载节点，微信仍保留image。

2026-11-20多条渔获：沿用已确认的安静内容面和Pro表单，不另开复杂录入页。Apple `entering-data.md › Best practices` 的明确字段／就近校验、`text-fields.md › Best practices` 的逻辑输入顺序和 `disclosure-controls.md › Best practices` 的按需展开用于「渔获与钓法」。UI UX Pro查询 `mobile form inline validation` 命中 Inline Validation、Focusable Error Summary、Submit Feedback：错误留在字段旁，提交失败聚焦可跳转的错误摘要，保留全部草稿。普通手机上鱼种占整行、尾数和重量并排；320px与大字自动纵排，数字单位始终明确。移除可撤销，新增／移除触区至少48px；不增加颜色、动效、仪表盘或导航。真实截图发现大字下“收起”拆行，已禁止该短动作拆字；375px数字并排减少滚动。实际检查320/375/440、横屏、宽屏、150%文字、减少动态及三套皮肤明暗；设备键盘和读屏仍须真机验收。

2026-11-19真实界面补充：依据 Apple `hig/images.md › Best practices` 的图片完整呈现与 `hig/accessibility.md` 的语义／字号原则，详情页改用既有完整比例图片模式，列表仍用缩略图；聊天复用 Pro 原生输入属性适配而不新造控件。UI UX Pro 的 `upload error recovery` 查询命中就近恢复和可访问错误提示，因此上传失败保留正文、保留单张重试并加 `role="alert"`。Vue表单检索建议的额外验证库不适用于此次小修，未引入。截图审查补充短聊天占位文字和重复渠道名称去重；不增加视觉装饰或新的操作入口。

钓友在水边、强光和夜间都要能读清内容，单手快速记录。沿用 Pro 移动组件，默认湖畔青皮肤；身份来自真实渔获、鱼情字段与地点隐私。

## 验收

评论区沿用现有皮肤与 Pro 的按钮、输入框、删除确认，不增加头像装饰、气泡或层层缩进。按 Apple `lists-and-tables.md › Content / Style` 保持可扫读的文字列表；引用是两行摘要，正文完整显示。最新评论在前，每批30条显式加载更多，服务端总数独立于当前已加载数量。选中回复后焦点进入带标签的输入框；取消只清除回复关系，不清除已写文字。320px、150%字时回复提示和取消操作自动换行，不挤窄姓名。

按 `alerts.md › Best practices / Buttons`，无法撤销的删除有明确说明、取消和“删除评论”；保留 Pro 的 Escape、焦点限制与取消初始焦点。UI UX Pro 检索“confirmation destructive delete”的确认与反馈规则用于此处，成功提示在原位，不再增加弹窗。引用使用 `reed/inset`、正文用 `ink/paper`，三皮肤明暗的语义对比测试均不低于4.5:1；操作目标至少48px。实际检查320/375/440、844横屏、1280宽屏、大字深色及删除弹层截图。页面返回时先清除旧引用文字、重新核验；原回复不在首批结果时保留输入但禁止误发为普通评论。

地图本轮按 Apple `maps.md` 的清楚选中范围、保留底图与图商标识，以及 `search-fields.md` 的输入即查找组织：联想紧跟输入框，移除多余搜索文字；草稿实线圈和社区虚线圈同时用说明区分，不只依赖颜色。UI UX Pro 的渐进披露、错误恢复和键盘规则用于日期/来源折叠、原位重试、上下键/Enter/Escape和中文输入法。圈选编辑时收起其他详情，表单复用Pro，不加入仪表盘或装饰图。

真实高德底图和圈线在320/375/440、横屏/宽屏、深色及150%字体验证；业务数据用明确标注的隔离样例，未写入远端。公开官方原文与社区提醒分开，审核通过不等于官方划界。参考范围首版为中心加半径，不是全国完整禁钓GIS。交互与证据边界见实施状态中的地图补充。

账号扩展沿用本节登录视觉规范，新增设置与找回密码的两步表单及手机号换绑流程。常规输入／主操作56px，密码显隐48px触区，Wot标准眼睛图标居中；原手机号只显示掩码，表单错误保留输入。已实际查看常规、320px、深色、大字、错误和完成截图；网页21项接口拦截检查通过。代码、服务端配置与真机边界见[账号登录与安全](account-security.md)。

在 320、375、414px 与宽屏检查溢出与固定栏遮挡；放大字号、切换夜间、打开键盘和减少动态设置；验证 H5 键盘焦点与读屏名称；微信模拟器和真机检查胶囊、授权与地图返回；Android/iOS 检查返回、权限、认证和键盘。选择、未读、危险与位置范围都由文字或图形补充颜色。示例数据始终标明示例状态。

2026-11-20 评论输入区：按 Apple `toolbars.md › Actions` 将常用轻图标放在前侧、唯一发送动作放在尾侧；`text-views.md › Best practices` 保留可缩放原生多行输入；`icons.md › Best practices` 沿用现有 Bootstrap 线性字形及可访问名称。UI UX Pro 查询 `icon button accessible label`（icons）命中 `icon-context-accessibility`，仅采用语义标签和同一图标家族规则。视觉外壳、120 个 Unicode 表情及四分类选择都放在 Pro；业务上传队列、回复权限和提交仍在钓友集。输入和附件共用一个圆角面，字数／附件统计在整个边框外侧右对齐；浏览器隐藏拍照，原生能力通过独立适配器提供。

实际验收含 320/375/440、横屏、宽屏和 320 深色 24px 字号，空输入／混合附件／上传失败／回复状态均留存截图。工具图标和发送触区至少 48px，始终同排，正常／深色发送前景与背景实测均达到 4.5:1。评论与回复聚焦时把真实 `MobileField` 样式节点重新移至文档末尾模拟热更新顺序，再逐层检查原生 textarea、Uni 包装层及父容器：内部无边框、可见轮廓或阴影，仅外框显示焦点；工具栏键盘焦点保留。小图格点击中心可预览真实本地视频帧，删除不抢播放点击，表情保持光标插入、500 字限制和关闭回焦。上述接口和上传为隔离测试，不代表远端发送、手机拍照或设备权限验收。
