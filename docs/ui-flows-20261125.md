# 发布、评论与设置打磨 · 2026-11-25

## 结果与方向

本轮使用项目内 Apple Design、UI UX Pro Max、Ponytail 以及项目界面／代码质量约定。以实际 H5 页面为基准，按可用空间和文字大小重排，再对照微信与 Android。总评 Good；真机、系统大字和 iOS 验收仍待完成。

三个页面的职责分别是完整记录一次鱼情、在原文上下文中回复、清楚找到设置项。沿用现有三套皮肤、系统字体和语义颜色；主要操作保持醒目，正文至少 16px、操作触区至少 48px。身份仍来自鱼形和钓鱼内容，本轮通过层级、留白和文案打磨。

布局沿用现有 Pro 容器：窄屏纵向排列，宽屏保持居中的阅读宽度，鱼情详情内的字段按剩余空间排成列。

```text
窄屏                         宽屏
标题／类型                    ┌──── 居中内容栏 ────┐
内容与附件                    │ 标题／内容与附件  │
选填详情（按需展开）          │ 选填字段按空间分列│
分享范围与位置                │ 分享范围与位置    │
唯一主要操作                  │ 唯一主要操作      │
                              └───────────────────┘
```

## 已完成的改进

- **High，发布错误后的展开逻辑。** 复现了正文和位置为空时，额外展开鱼种、钓法等整个选填区。现在只有计量、日期或具体渔获行出错才展开详情；错误摘要仍获得焦点，字段错误及已填内容保留。
- **High，回复上下文与大字排版。** 鱼情回复区增加原评论的两行摘要，纯附件显示对应提示。320px／200% 文字下，作者与取消操作按空间重排，避免昵称被挤成很窄的一列；取消回复保留输入。钓位评论的长水域名、评论总数和取消操作也允许重排。
- **Medium，计量说明可持续阅读。** 尾数、鱼长和重量的说明移至输入框下方，输入框使用简短占位。填写后仍能看到「空军填 0」等规则，大字时说明可以换行。选填标题、选填说明、展开状态分开呈现，减少括号与孤字换行。
- **Medium，发布等待状态。** 提交等待期间统一禁用类型、文字、计量、选择器和展开操作，并暴露忙碌状态。隔离接口检查验证失败后恢复编辑、保留正文及 0 尾数；重试提交同一份内容。
- **Medium，设置列表层级。** 设置项名称与用途改为固定的上下两行，主次文字保持相同起始位置。三套皮肤的名称、预览与勾选保持原有行为；主题保存失败时，提示与重试按钮在大字下各自保留完整空间。

Apple 依据为已读取的 `layout.md › Visual hierarchy / Adaptability`（“Be prepared for text-size changes.”）、`entering-data.md › Best practices`、`text-fields.md › Best practices`、`toolbars.md › Actions / Item groupings`、`settings.md › Best practices`，以及 accessibility、typography、color、buttons、sheets、designing-for-ios 和跨平台参考。采用其清楚输入、保留上下文、文字重排和动作层级原则，按 Uni-app 现有组件实现。

UI UX Pro Max 查询 `form error summary recovery` 命中 Focusable Error Summary、Error Recovery；`text reflow narrow toolbar` 命中 Text Reflow and Spacing、Chip Collection Reflow。H5 同时检查 [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 的就近错误、焦点、文本容器与弹层要求。
