# 账号登录与安全

## 账号规则

- `auth.users.id` 是账号唯一标识，`profiles.id` 与之对应。首次短信登录由认证服务创建账号，现有触发器创建钓友资料；已有手机号再次登录沿用原 UUID。
- 钓友号固定，昵称在个人资料页修改。设置密码后，可使用钓友号或手机号加密码进入同一账号；没有默认密码，也不另外创建“密码账号”。钓友号在「我的 → 设置与隐私 → 账号与安全」查看和复制。
- 手机号换绑修改同一认证账号，不迁移或重建日志、好友、收藏等数据。手机号不公开展示。
- 页面保留“先逛逛”，不因新增密码功能强制注册。

## 已接入的真实接口

| 流程               | 顺序与边界                                                                                                                                                                                     |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 短信登录／首次注册 | `POST /auth/v1/otp`，`create_user=true`；`POST /auth/v1/verify`，`type=sms`；仅接受完整、未过期的真实会话                                                                                      |
| 密码登录           | `POST /auth/v1/token?grant_type=password`，提交手机号与原样密码；错误可转短信登录或找回密码                                                                                                    |
| 钓友号密码登录     | `POST /functions/v1/account-login`；服务器用既有 `profiles.handle` 取得 UUID、读取当前绑定号码，然后调用同一原生 password grant；仅返回 UUID、手机号一致的完整认证会话，不提供公开号码查询接口 |
| 设置／找回密码     | `otp(create_user=false)` → `verify(sms)` → `PUT /auth/v1/user {password}`；验证期间的临时会话只留内存，保存成功才安装登录状态                                                                  |
| 换绑手机号         | 认证读取当前手机号 → 验证原手机号 → `PUT /auth/v1/user {phone,channel:sms}` 发送新号码验证码 → `verify(type:phone_change)` → 核对原 UUID、新手机号后保存会话                                   |
| 重启／前台恢复     | 读取设备保存的会话，必要时通过原刷新令牌换新；网络错误保留凭据，明确的失效或撤销才退出                                                                                                         |

找回密码不创建新用户。已登录账号的验证结果必须匹配原 UUID 和手机号；新号验证码不能作为新用户登录使用。手机号被占用时原账号不变。换绑完成后尝试退出其他会话；未能确认时提示，不能伪报全部设备已退出。

原手机号验证在本次页面流程内保留 5 分钟。该流程约束不等于认证服务提供了“强制新旧号码双重验证”的全局配置：认证服务自身仍以有效会话和新手机号验证码裁决换绑。密码重新验证使用认证服务原有策略；并未伪造不存在的安全换绑开关。

首次短信登录后进入「设置密码」，可复用当前会话中 15 分钟内的 SMS/OTP AMR，直接展示第二步，避免为刚完成的验证再次发收费短信。页面先读取 `/user`；保存仍由 Auth 验证原 JWT。密码登录产生的会话、过期／错号／错 UUID 的 AMR 均不能跳过此步骤。借用当前会话时，取消设置不会撤销当前登录；独立找回及换绑验证的 5 分钟期限不变。

钓友号接口使用服务端专用的 `fishing_account_login_ticket`：同号每分钟最多 5 次、每小时最多 20 次、全项目每分钟最多 60 次。计数器在私有 schema，RLS 和强制 RLS 开启，无客户端 policy；仅 service_role 可调用 SECURITY INVOKER 函数。缺号和错密码统一响应，不回传手机号；号码换绑竞态核对 UUID，拒绝并撤销未返回的错误身份会话。限流出错时拒绝登录，手机号原生登录仍保留。凭据不进入表、日志或代码。

密码保存由认证服务处理哈希与其他会话撤销。已签发的访问令牌可能在到期前仍有效，不承诺所有设备即时失效。密码不写入资料、浏览器存储、日志或本机安全存储。

## App 登录状态

- 使用固定版本 `@aparajita/capacitor-secure-storage@8.0.1`，Android 使用 Keystore 保护的加密存储，iOS 使用 Keychain。
- 仅原生平台调用安全存储；网页／小程序延续各自的本机存储。原生失败不回退到明文存储。
- iOS 关闭 iCloud 同步，选择 `whenUnlockedThisDeviceOnly`。新安装标记缺失时只移除钓友集自己的会话键，避免卸载后残留 Keychain 自动进入旧账号。
- 启动恢复完成前，页面显示鱼形标记与恢复状态；随后由原有账号上下文重新加载私有内容。
- 通用凭据队列归属 Pro 的 `packages/mobile-core/src/credential-store.ts`，按顺序读写、轮换、移除，防止旧写入在退出后完成。业务会话使用代次与账号范围拒绝迟到结果。
- 前后台切换不会把找回密码／换绑流程当作离开页面；查看短信后保留步骤与倒计时。离开并销毁页面时撤销未使用的临时验证会话；密码输入在隐藏时清空。
- 锁屏期间读取失败不删除安全凭据，回到前台可再次恢复。主动退出移除安全会话并按原规则清理本机私人草稿。

## 视觉与输入

按本仓 `apple-design` 的 managing-accounts、entering-data、text-fields、accessibility、icons 参考，以及 `ui-ux-pro-max` 的错误恢复、触区与渐进披露规则实现。沿用既有湖畔青和鱼形品牌，不增加装饰层。

- 主操作与输入常规高度 56px，显隐密码按钮触区 48px。验证码输入与发送按钮顶部、常规高度一致；大字和长倒计时时允许换行。
- 密码显隐使用现有 Wot `eye/eye-invisible` 图标；按钮有可访问名称、按下状态和键盘焦点。共用表单修改归属 Pro，生成核心只同步。
- 验证码使用单个完整输入，H5 `type=text`、`inputmode=numeric`、`autocomplete=one-time-code`，保留前导零。提交时读取输入当前显示的值，处理 Uni 模型更新前的系统填充。
- 手机号使用 `tel`／密码模式 `username`，密码分别使用 `current-password` 与 `new-password`，允许粘贴和密码管理器。
- 协议按用户要求默认勾选，图标和“我已阅读并同意”均可切换；协议链接独立打开。取消后阻止发送和登录。
- 系统是否提供验证码建议取决于设备、微信版本和短信模板。未接入 Android WebOTP 自动读短信；不能把本地输入事件当作真实收码自动填充验收。

- 密码变更重新验证开启；允许通过新近短信验证恢复忘记的密码，不要求已忘记的旧密码。

- 手机号认证与既有短信 Hook 路由启用，自动确认关闭，OTP 为 6 位、300 秒、60 秒发送间隔。
