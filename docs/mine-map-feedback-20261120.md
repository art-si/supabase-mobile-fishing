水域线索是本人私密保存的现场材料；社区举报是内容、评论和钓位纠错的处理记录。个人页改为“我的社区举报”并给两项入口各一行用途说明，提交结果和返回入口同步命名，避免将两种数据合并。

实际复现了H5热更新故障：Pinia保留原来的已登录计算状态，但session模块被重新求值，请求改为不带凭据。只对登录状态相关模块采用Vite官方完整刷新方式，统一恢复会话。回归测试真实触发文件更新，断言文档重新加载及两个私密列表请求都带同一账号的凭据。它不修改生产登录协议，也不伪造短信。

地图加载失败使用居中品牌空状态、具体恢复文案和两个48px操作：重新加载、查看钓位列表。加载失败时不显示无法使用的圈选／定位动作；钓位查询无结果则保留真实底图，在底部给出安静的换区域提示。错误和无数据分别呈现。

设计依据：Apple `layout.md › Visual hierarchy / Adaptability` 的对齐、分组和字号适应，`typography.md › Conveying hierarchy`、`feedback.md › Best practices` 的就近状态和可恢复操作，`maps.md › Best practices` 的底图交互，`loading.md › Best practices` 的明确加载反馈。UI UX首次 `profile card visual hierarchy` 偏向Web悬停／面包屑，未采用；收窄到 `responsive hierarchy spacing` 后采用Touch Spacing与Text Reflow and Spacing。沿用现有语义色、字号和48px控件，不引入新皮肤。

## 比例纠错规则

用户明确确认了至少10个账号、60%认为可以垂钓时自动解除应用围栏，适用于钓友与官方来源标记。该结果改变应用地图显示，原公告、原边界和发布状态保留，页面明确这不代表管理规定已变更。

| 条件 | 应用行为 |
| --- | --- |
| 少于10个有效账号 | 保留现有围栏；6/9也不能解除 |
| 至少10个账号，认为可以垂钓达到60% | 自动解除围栏；6/10恰好生效 |
| 解除后认为仍需禁钓达到60%，且至少10个账号 | 恢复围栏 |
| 双方均未达到60% | 保持上次状态，避免50/50反复闪现 |
| 原边界、依据、期限或社区版本变化 | 新计票轮次，旧轮次和处理记录保留 |
| 原记录撤回、隐藏、过期或不可见 | 不能继续投票，也不能靠投票恢复原记录 |

一账号一票，可修改；账号标识来自服务端`auth.uid()`，客户端不能传投票人或人数。重复重试不增加票数或解除事件；对同一围栏加事务级锁，避免并发第10票丢失。来源版本由服务端内容指纹生成，旧版本投票被拒绝。这里计数的是不同账号，不声称验证了现实中互不关联的自然人。

业务实体：原始来源表拥有政策和边界；私有`zone_feedback_rounds`拥有应用显示结果；`zone_feedback_votes`保存每账号当前选择与选填依据；`zone_feedback_events`保留投票和解除／恢复审计。新表启用RLS且不给客户端原始表权限；公开接口只返回汇总和当前账号自己的反馈，不返回其他投票人、其补充说明或审核身份。游客可查看汇总，提交需登录。

`fishing_zones_read('nearby')`在服务端划分有效围栏和`released`记录，游客／其他设备重新读取也得到同样结果。地图立即移除已解除的SDK覆盖物，区域列表保留“钓友反馈已解除”入口，后续仍能查看来源和反馈。打开列表重新读取，切账号或离页清理旧请求和私有说明。

## 来源采集与覆盖边界

回读发现原有5条政府公告候选全部未公开，原因是没有完成水面核对，而不是全国地图已有完整数据。解决了本机采集程序未使用环境代理导致请求超时，以及官方水面交集被误套钓友120点、单环限制的问题。官方输入按现有数据库的4000点／64环限制核验，普通钓友圈选仍保持120点单环。

本轮将农业农村部公告核心区坐标与OpenStreetMap团氿水面相交，保留岛屿空洞；原候选仍不公开。水面来源、许可归属和检查日期随记录保存并在详情显示。法规依据为[江苏省渔业管理条例](https://www.jsrd.gov.cn/qwfb/sjfg/202606/t20260603_1335317.shtml)，核心区拐点为[农业农村部第八批公告](https://yyj.moa.gov.cn/bjwj/201904/t20190419_6197404.htm)，水面为OSM relation 1113557。不是全国完整GIS，也不是测绘级岸线。

其余4条候选的OSM名称与公告对象不一致（圣水湖／竹山县水库、琵琶湖／大洪山水库、胭脂湖／鸭子湖、南湖／镜月湖），不能只凭相交便确认同一对象，保留未公开原因。没有盲目使用别名匹配。

公园／电站候选见`data/official-zones/source-candidates.json`：南、北太子湖公园先核对管理范围与水面，适用规则是未经批准不得垂钓；定南县公告明确了天成桥至长滩电站河段，仍待河段边界。武汉补采曾返回429，没有用POI半径或示意图代替。采集顺序是“有效公告／管理规定 → 对象和位置 → 边界与水面交集 → 本地SQL校验 → 项目级MCP部署 → 普通公开API回读 → 真实底图截图 → 钓友反馈”。未取得符合条件的数据前不批量公开。

采集程序默认只写预览SQL，拒绝覆盖已部署迁移；显式导入要求CLI新建空迁移。本轮新增`20261120102801`比例反馈与`20261120102802`核验水面迁移，未改历史迁移。MCP自动记录的UTC编号在回读后与仓库依赖顺序对齐。
