# 图文发布与照片顺序

> 当前规则：鱼情和钓位由作者保存即发布，编辑后在原记录生效，无需审核。新建默认公开，已有草稿和记录保留原分享范围；读取时继续判断公开／好友／仅自己权限。对应迁移为 `20261120102200_fishing_posts_direct_publish.sql` 与 `20261120102803_fishing_spots_direct_publish_location.sql`。下文待审内容为历史验收记录；当前钓位和水域地图见 [本轮交互](spot-map-update-20261120.md)。

## 规则与责任

- 动态（心得／渔获）：正文或已上传照片至少一项。标题选填；只有标题、鱼种或空白字符不能发布空动态。
- 私人出钓日志：标题、有效日期必填；正文、照片和渔获条目可留空。未知测量与零尾数仍按原规则保存。
- 标题60字、正文2000字、照片最多9张。前端使用统一限制，服务端独立检查；绕过界面不能提交空内容、重复／缺失照片ID、错误类型或超限数组。
- 标题为空时不写入编造的标题。列表可直接点击正文，详情不重复正文；纯照片入口、审核、聊天卡片和通知用只读摘要或「渔获照片／心得照片」。作者编辑仍得到原本的空标题。
- 照片属于上传账号，只能绑定本人的这条记录或尚未绑定的资源。不能挪用他人、其他动态／日志、聊天或线索材料的照片。
- `sort_order` 保存0–8的展示位置。创建、编辑和读取一致；旧数据按此前的上传时间／ID顺序回填。排序与正文、版本更新和附件绑定同一事务，失败全部回滚。
- 创建重试沿用记录ID，编辑重试沿用请求ID和版本检查。旧请求不能把已经调整的照片还原为旧顺序。删除附件先解除记录绑定，不删除用户原片；移除全部照片时必须保留正文。

## 交互

点照片预览；「调整照片顺序」打开一个Pro底部弹层，从上到下为展示顺序，前移／后移支持点按与键盘。首尾边界按钮禁用，移动后文字播报，Escape／关闭回到触发按钮。没有强制拖拽、额外导航、动画或新颜色。

上传中不允许排序／移除／重复重试／保存。单张失败保留正文及已上传结果，可重试或移除；返回本机草稿保留已上传照片的顺序。刷新草稿按当前账号重新签名私密照片，不使用过期链接或把存储路径当图片地址。会话失效或切号立即移除照片排序弹层并关闭预览，不把旧账号照片带入新账号。

原有本机未成功上传的临时图片不是可靠的跨重启草稿：重新启动后需要重新选图；不会用演示图替代。成功上传的照片可恢复，界面明确显示上传失败。
