## 实际入口与能力边界

2026-11-26 的访客实测中，武汉公开媒体钓位由 3 条增至 9 条，H5 连同社区钓位共显示 10 条。武昌江滩卡片提供 1 号门导航入口，以及 B 站原片 01:21 的鱼获截图。每 3 天上午 9 点的本机定时任务优先查找钓友发布的野钓原片。

每 3 天由本项目的 Codex 定时任务浏览公开野钓视频，记录地点线索并从原片截取实际鱼获。浏览器核验与服务器的免费频道轮询共用公开目录。遇到登录、验证码或读取限制时保留待核验状态。

393 个城市名与前端城市目录一致，区县索引由项目固定版本的 `@vant/area-data` 生成。区县归属帮助识别只写县名的地方报道；最终仍核对高德返回的城市与区县。

当前注册 41 个免费频道，2026-11-23 从 Supabase 服务端逐批实测 39 个可读。江门栏目返回 403，云南站首页没有足够可识别原文链接，未计入可用来源。这是频道可读数，不是媒体合作数或已经发布的钓位数。55 个媒体域名是解析白名单，393 个城市是识别目录，均不能当作已有钓位的城市数量。2026-11-23 首次验收有 4 个公开地点。采集源免费；地点核对和可选的模型提取复用项目既有高德、Art 服务及其原有额度。

## 发布条件与生命周期

`queued → processing → published / review / blocked / failed`。每次原子领取最多 3 个来源和 1 个城市，租约 5 分钟。并发领取使用 `FOR UPDATE SKIP LOCKED`；迟到或重复完成不能改变新租约的结果。网络和模型故障按指数退避重试，资料待核验/受限则延后检查。

经营钓场需要一年内的有效原文、垂钓证据和高德的唯一匹配地点。野钓可采用作者的原始定位，也可采用视频画面或字幕明确指向的具体入口与岸边地标。入口和岸段参考点分别标明精度，保存来源链接、取证秒数及同名高德 POI。禁钓、停业、单次赛事等条件仍按原有流程筛查。

坐标来自当前规范原帖的 `contentLocation.geo`（Schema.org WGS84）或包含明确地点名、坐标系、经纬度顺序的正文片段。忽略作者住址、发布者位置、推荐视频、裸数字和多地点歧义。WGS84 使用高德坐标转换后做逆地理编码核对城市与已知区县，再执行禁钓范围检查。保留原始坐标、坐标系、原文位置证据及来源 URL；模型不能生成坐标，运营或导入提示也不能绕过原文重读。

取得高德位置后还调用与创建钓位相同的禁钓范围校验，命中生效禁钓范围不发布。数据库触发器与目录 RLS 也校验当前范围，不能绕过前端或用旧核验结果覆盖新禁钓信息。未命中只表示未命中当前已收录范围，不是合法垂钓许可。

分享收件箱只从 `public + published` 的社区钓位读取描述外链，不采集私密、好友、待发布内容或设备 GPS。描述变更使旧租约失效；转私密、隐藏和删除取消尚未完成的领取。完成时再次校验公开状态及内容指纹，只入队城市和规范 URL，钓友自己的描述不会升级成原文证据。已经独立核验的第三方公开原文仍按自身生命周期管理。

原文核验表示来源和地点在该时间通过检查，不代表现场营业调查。来源发布日期与核验日期分别保留在卡片详情中。高德 POI 标为高德地点，原文坐标标为作者分享定位；前端既有地图定位实现直接复用。

发布后每 7 天重查，14 天未重新通过就不再对外展示。发现禁钓、停业、404/410 等情况撤下或转待核验。经营场所按同城高德 POI 合并；原文定位按同城 GCJ-02 坐标身份合并，不制造 POI 编号。保留既有卡片名称以延续点赞、评论、收藏，同名但不同地点进入待核验。社区钓友自行发布的记录独立管理。

旧目录没有自动获得核验日期：先进入核验队列，未通过的条目不对外展示，前端也不回退到旧内置目录。原始卡片与互动键保留供核对。

待核验不等于假资料。页面结构、缺少准确地点名、暂时无法读取、模型漏掉正文都可能造成待核验。修正正文解析并重新核验后，可恢复有实际依据的旧记录。

## 部署与维护

### 视频原片补录

每次查看原片后记录当天的 `reviewedOn`。武昌江滩的[核验记录](../data/spot-source-evidence/BV1ds5f6cEFQ/review.json)包含入口字幕、鱼获 JPEG 和取帧时间。只有亲眼确认有鱼获的原片才填写 `frame`。发布时重新查询高德，核对城市、区县、POI 名称及坐标，并在事务内检查现行禁钓范围、图片存在性和来源租约。

```powershell
node --experimental-transform-types scripts/spot-video-review.mjs frame <review.json>
node --experimental-transform-types --env-file=.env.amap-web-service.local scripts/spot-video-review.mjs publish <review.json>
```

在已确认的 Fishing 项目管理连接中执行各命令生成的 SQL。第一步通过服务端凭据将 JPEG 存入独立的公开鱼获图库，回读返回的请求编号确认成功，再执行发布 SQL。相同文件按 SHA-256 复用。无图作品直接执行发布步骤。最后以匿名身份调用 `fishing_list_spot_leads`，在 H5 用地点名搜索并打开图片预览。每轮同时复看临近到期且须浏览器取证的视频。

- 数据迁移：`20261123030929_fishing_spot_source_pipeline.sql`；本地迁移名与远端回读版本一致。
- 地点提示迁移：`20261123033038_fishing_spot_source_place_hints.sql`。运营可在来源清单的 `places` 中提供原文地点全称和查询简称，必须在实际抓取内容中找到才能采用；不提供经纬度、不跳过核验。
- 来源合并迁移：`20261123035053_fishing_verified_source_links.sql`。公开卡片不能继承未经核验的旧来源链接；同城其他来源需有最近 14 天内成功核验的记录。
- 标注租约迁移：`20261123040926_fishing_source_annotation_leases.sql`。修改运营标注即使旧任务仍在运行，也会重新排队并使旧租约失效。
- 地点身份迁移：`20261123042300_fishing_spot_identity_guard.sql`。同名但不同 POI 的材料进入待核验，不合并到旧卡片。相同 POI 保留互动键，`displayName` 展示原文中的真实名称。
- 查询别名迁移：`20261123050315_fishing_spot_poi_alias_guard.sql`。相同查询简称不能覆盖已经匹配到另一个 POI 的卡片；保留旧名称的兼容匹配仅用于尚无 POI 编号的旧记录或同一编号的地点。
- 禁钓创建守卫：`20261123063126_fishing_spot_prohibition_guard.sql`。新建、移动位置、来源发布与公开目录均使用当前有效禁钓范围。
- 野钓坐标：`20261125094531_fishing_wild_spot_coordinates.sql`。发布校验接受有原文坐标证据的自然水域、水库；保留旧 POI 路径、租约、有效期、RLS 及互动键。完成接口与地点身份助手仅允许服务端调用。
- 公开分享收件箱：`20261123065659_fishing_public_share_intake.sql`。每轮最多领取 5 条公开描述，租约 5 分钟，只有服务端可调用领取和完成接口。
- 函数：`spot-source-sync`；同步更新 `spot-source-import` 和 `spot-discovery`。
- Cron：`fishing-spot-source-sync`，每 5 分钟运行。每次轮换读取 3 个 RSS 或公开栏目，41 个频道约 70 分钟轮询一遍；失败不阻塞其他频道或已排队来源。无固定城市的栏目先读取原文再判定城市。
- 鉴权：Vault 中的专用随机令牌；只允许服务端校验。普通用户 JWT、公开 Key 均不能调用采集队列。令牌不返回前端、不写入代码或日志。
- 复用项目现有 Art 和高德服务端配置。采集不要求访客登录，不在访客请求里调用模型或媒体搜索。
- `fishing_private.spot_source_runs` 保存 30 天执行摘要及待核验原因/地点名称，表与任务队列均开启 RLS，普通用户不可读写。

验证、生成入队 SQL：

```powershell
node scripts/spot-source-maintenance.mjs validate
node scripts/spot-source-maintenance.mjs queue data/spot-source-seeds.json
```

生成的 SQL 应通过已确认项目的管理连接执行。重复入队不会重复生成任务。人工核对某来源后，可用管理连接将其 `next_check` 提前；不要手工把待核验记录改成已发布。

复杂的多场所文章可在 `places` 中补充运营逐段核对过的 `name`、`query`、`district` 和最多 90 字的连续原文 `evidence`。后台仍重新读取正文，检查名称、证据与城市依据，并查验真实高德 POI；不能只凭标注发布。只有明确属于经营园区的材料才可加 `managedVenue: true`，正文仍须出现园区、景区、农庄、营地、生态鱼塘或垂钓园依据。模型输出的证据不会自动升级成运营标注。

```sql
select city,url,state,reason,checked_at,next_check
from fishing_private.spot_source_jobs order by checked_at desc nulls last;
select started_at,summary from fishing_private.spot_source_runs order by started_at desc limit 10;
select fishing_private.dispatch_spot_sources();
```

服务端可使用同一专用令牌向 `spot-source-sync` 发送 `{"operation":"check_channels","offset":0,"limit":10}` 分页检查固定频道；每批最多 10 条，不接受外部 URL，也不修改公开钓位。

首批种子只列出真实原文链接，不等于已经通过核验。实际公开数量、各来源失败原因和截图验收见[本轮验收记录](spot-source-validation-20261123.md)。小程序/原生仍需真机检查。
