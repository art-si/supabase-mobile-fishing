# 钓友集跨端布局打磨 · 2026-11-23

## Summary

评估：Good。保留「简单、实用、大气，内容优先」的方向，以鱼情记录、清楚的内容层级和安静的实色卡片形成识别。此次主要消除 H5 与微信的字体、可用宽度、触区和评论编辑器留白差异；物理手机的系统字体与键盘仍须单独验收。

## 依据与已修复问题

- **High，已修复：两端字体和窄屏阅读宽度不一致。** H5 原有正文字库与微信系统字体的字形、字重、换行不同；窄屏 H5 还保留了桌面滚动条槽。现在共用 Pro 系统字体栈、同源图标和皮肤 token，窄屏不预留桌面槽。Apple `typography.md › Ensuring legibility`：“Use font sizes that most people can read easily.”
- **High，已修复：大字长评论被编辑器遮挡。** 取消 H5 独有的 sticky 编辑器，统一为评论之后的正文流；长昵称、时间和管理动作分别排布，不用负边距拉齐。Apple `typography.md › Supporting Dynamic Type`：“Make sure your app’s layout adapts to all font sizes.”
- **Medium，已修复：微信空编辑器存在额外留白。** 条件插槽在微信仍有声明，空回复和字数区仍会产生边距；空上传器中的原生节点也能产生网格间距。Pro 增加可选的 `showReply` / `showMeta`，两个钓鱼评论入口传入实际状态。空附件通过上传器自己的状态类隐藏，实例保持挂载，选择失败说明仍可显示。
- **Medium，已修复：小文字和紧凑触区。** 正文至少16px、昵称至少14px、辅助文字至少12px；首页头像、分段筛选和图标按钮采用48px触区。360px以内卡片内边距16px，常规20px。Apple `layout.md › Visual hierarchy`：“Align elements to make them easier to scan”。
- **High，已修复：微信主题切换后互动文字偏暗。** 实际深色截图发现评论昵称和互动行仍依赖CSS媒体查询，未跟随应用主题变量。现将 `discussionName` 接入三套皮肤和 Wot root portal，与其他语义色走同一来源；浅深色沿用原有蓝色值。
- **Medium，已修复：本机体验的微信地图页空白。** 说明被浮动搜索区盖住，且缺少下一步。现在与H5共用空状态组件、说明和「浏览示例钓位／返回上一页」动作，禁用体验中不可用的搜索；钓位详情不显示体验中不可用的静态地图请求入口。

已阅读项目 Apple Design 的 layout、typography、accessibility、color、buttons、sheets、dark-mode、tab-bars，以及 cross-platform / code-audit 参考；以 H5 和微信平台行为落实原则，不直接复制 iOS 专用组件。

UI UX Pro Max 查询 `mobile touch target consistency`，采用 Touch Target Size、Touch Spacing、Touch-Friendly 的匹配规则；配合 `references/pro-rules.md` 与 `quick-reference.md` 的可读性、焦点、响应式和深色要求。Vue 查询 `reactive component styles` 仅提供通用响应式/SFC建议，未据此新增依赖或重写业务逻辑。

## 最终布局约定

| 区域 | 约定 |
| --- | --- |
| 字体 | 所有端同一平台字体栈；图标字体保留 |
| 正文 / 昵称 / 辅助字 | 下限16 / 14 / 12px，随 rem 向上缩放 |
| 底栏标签 | 12–22px，保留完整文字与足够触区 |
| 卡片 | 20px圆角；常规20px内边距，≤360px时16px |
| 主要触区 | 48px；纯视觉图形可以更小 |
| 评论 | 昵称与时间可换行，管理动作独立；正文位于头部之后 |
| 编辑器 | 跟随评论正文，只有存在的回复、附件和计数占空间 |
| 安全区 | 胶囊、状态栏及底部空间按设备实际值计算 |

```text
头像  昵称                 类型
      日期 · 城市
标题（如有）
正文
鱼种 / 钓法 / 饵料
地点                     ›
点赞        评论        收藏
```

保留三套皮肤和既有语义色。静态配色测试覆盖三套皮肤、明暗两种模式共84组文字/背景色对（本轮新增18组评论文字色对），均达到至少4.5:1。没有增加装饰、营销区域或与内容无关的新功能。

## 平台边界

H5 和小程序共用视觉规则，不抹掉微信胶囊、安全区和真实可用能力。相机入口按平台能力显示。此次没有修改数据库、RLS、Edge Function 或线上业务数据。

同尺寸比较使用实际编译后的 H5 和微信模拟器，各记录宽高；微信底部安全区保留34px，比较外层编辑器高度时单独扣除它相对 H5 的26px差值。1px内的差异作为渲染舍入处理。开发者工具2.02的自动化计算样式接口存在跨上下文错误，因此微信颜色/字体以共享源码、配色测试和实际截图审查为证，不声称通过该接口读取了微信计算样式。

物理 iOS / Android 微信的系统字号、输入法、相册、相机、真实GPS和读屏操作尚未在本轮完成；模拟键盘高度事件只能验证布局响应。
