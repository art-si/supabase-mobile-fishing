# 评论图片和视频

评论沿用现有上传、媒体预览和评论治理。`comment` 写入接收 `{ id, post_id, reply_to_id?, body, media?: [{ id }] }`；文字最多 500 字，图片和视频合计最多 6 项，可以只发表附件。附件顺序按传入数组保存，表情直接使用 Unicode 文字。同一请求 ID 仅允许相同文字、回复目标和附件顺序重试，不重复产生评论或通知。

新附件必须属于当前用户，且未关联其他动态、日志、线索、私信、钓位、头像或评论。`media_assets.comment_id` 受外键和单一父记录约束保护；所有旧的媒体挂载入口同时排除评论附件。公开、好友和私密动态的评论附件，必须通过动态本身的访问权限检查；上传者不能依靠附件所有权绕过已经私密的动态。隐藏评论延续已有治理规则，仅作者和满足条件的审核人员可读；拉黑、删除、动态权限变化会阻止后续媒体签名。

回复及通知使用简短的附件摘要，原始媒体只在有权访问的评论和审核详情中提供。删除评论、删除父动态及注销账号会删除附件索引，经现有耐久清理队列删除对象。清理链审计覆盖全部迁移、Edge Functions、服务适配和维护脚本：本项目没有按上传年龄或“未关联父类型白名单”扫描删除的作业，只有已提交的 `media_assets` 删除能入队，仍存在的索引也会阻止清理。账号注销按账号存储目录清理并级联删除索引，不依赖父类型白名单；没有现存账号数据导出接口需要扩展。

迁移为 `20261120102800_fishing_comment_media.sql`，已部署至确认项目并回读附件父记录、互斥约束、幂等写入、权限、评论返回及删除清理触发器，全部通过。证据在 `artifacts/comment-media-deployment/readback.json`。无需更改 Edge Functions：现有媒体上传已支持有界且经过处理的图片和视频，读媒体沿用 Storage RLS，清理沿用已部署队列。远端安全检查未新增告警，仅保留既有 Auth 泄露密码保护提示；未改变无关认证设置，也未写入用户评论或附件进行测试。
